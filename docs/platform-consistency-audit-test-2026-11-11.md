# Platform data consistency audit — test branch, 11 November 2026

Status: test-branch implementation and local verification; full deployed acceptance remains open. No production database/function deployments were made. The user's explicit `test` instruction overrides `test_v2` in the supplied brief. Main remains unchanged.

## Architecture and authority
- Seven school roles are implemented: principal, deputy, clerk, teacher, parent, security and SGB. Super Administrator uses the separate platform-administrator identity. No separate school-admin or security-supervisor role is implemented in the enum; management functions belong to the existing roles.
- `app.js` is the shared school renderer/data adapter. `getState()` consumes a server-loaded session cache, not seed data. `save_school_dataset(before,after)` applies tenant-scoped record deltas and rejects conflicting changes. `workspace-sync.js` also exists for versioned outbox/command support; the current school adapter uses its own confirmed/pending dataset path. These are transport mechanisms, not two authoritative databases.
- Core authority: schools/profiles/Auth, school_staff, teacher_review_classes/subjects, school_learners, school_guardians/learner_guardians, teacher_teaching_contexts. Triggers project canonical core records into school_workspaces for compatible reporting/operational APIs. Do not edit the core JSON as a second master.
- Operational authority: existing school_workspaces collections (visitors, incidents, assessments, reports, attendance, notices, appointments, announcements, ordinary conversations). Checked RPCs own dedicated operations. Teacher targets/reviews/support and SGB/security chat use their relational tables. Document metadata/private Storage own attachments. Notification read state is per-user notification_reads. Account-request/assignment notices use account_request_notifications.
- Platform authority: platform administrator membership, audited platform operations, school lifecycle/settings, school_branding/school_portal_themes, school_problem_reports/support and platform notification/read tables. Owner account settings use the owner's Auth identity.
- Shared refresh: initial RPC load, school_dataset_versions invalidation subscription, 15s fallback/60s healthy polling, focus/online/visibility revalidation. Branding refresh is separate. Personal notification reads have separate subscriptions and focus/online hooks.

## Findings recorded before implementation
1. Refresh race: `refreshCloudWorkspace` checks neither account identity nor request generation after remote calls. A late response may populate the cache after account/tenant switching, or overwrite a newer refresh. Existing save path already protects account switching.
2. Account revalidation: a school mismatch from the profile join is ignored and role/name are updated without forcing a new school context. A changed role must not keep the previous broader snapshot/draft.
3. Parent projection: `parent-workspace` copies full report/assessment/register/week objects, so new private fields can leak by default. Link query errors are treated as an empty family; read failure must be reported rather than returning a successful empty workspace.
4. Sick notice routing: `persist_parent_document_notice` creates a name-targeted teacher notification without recipientId/learnerId/class. The notification visibility guard explicitly rejects name-only targets. Staff can see the notice but miss the alert.
5. Chat write race: `parent-chat` performs an unlocked service-role read/replace of the full workspace and has no retry ID. Concurrent messages/other operational edits may be lost or duplicated on retry. Existing parent/teacher communication is enabled in current code; this task must not add new role communication paths.
6. Lifecycle: workspace Realtime channel/timers have no pagehide cleanup or explicit resume binding. Avoid duplicate subscriptions and restore revalidation on persisted-page return.
7. Evidence gap: existing database suites exercise selected migration stacks, not one full clean Supabase schema or real deployed Auth/Realtime/Storage. Historical audit documents describe old rollout gaps that later migrations addressed; they are not proof of current deployed defects.
8. Attendance writers also update protected learner collections and assume a 60-day baseline. Teacher saves can therefore fail authorization. Score submissions do not refresh stored learner averages. Derived dashboard values need one shared projection.
9. Report preview generates marks for missing subjects using character codes and learner averages. It selects the first assessment rather than the recorded subject average, ignores one academic-year field spelling, and prints a fixed year. These are operational report defects, not valid demo records.
10. Leadership priorities contain invented incident/shift deadlines; reporting defaults to Term 2 and an attendance workflow defaults to September 2026. These labels are not driven by school records.
11. Parent class averages are calculated from the linked learner subset rather than the full class. Private classmates must remain hidden while the intended class aggregate remains accurate.
12. Principal/Deputy raw workspace SELECT can bypass the checked conversation projection. No browser module still queries this table directly. The new migration revokes raw table/column SELECT grants while retaining existing RLS policies and checked RPC access.
13. The old session-cache key omits the role. A downgraded account can reopen its former privileged draft. Cache/draft keys now include the stable school ID, user ID and verified role. Old keys are retained, never auto-imported into a different permission context; recovery of old unscoped drafts requires authorized review.

## Changes implemented
- `app.js`: generation and account checks reject late/out-of-order reads and reads started before a newer mutation. A profile role/tenant mismatch requires a fresh sign-in/bootstrap. Display-name refresh still works. Pending drafts remain account scoped.
- Workspace polling/listeners/channels are cleaned up on pagehide and recreated once on persisted-page return, with immediate server revalidation. Existing initial loads, polling, online/focus/visibility refresh and authorized invalidation counters remain in place.
- `parent-workspace/projection.mjs`: explicit fields for reports/assessments/registers/week summaries; only linked score/entry/release keys; own submitted sick notices; correct recipient/class/learner notification filtering. Link-query failures return an error. A full-class aggregate is produced on the server without sending classmates to the parent browser.
- `parent-chat`: the function delegates to an account-checked transaction instead of replacing a privileged snapshot. The browser retains a stable request ID on retries and requires confirmed success. Existing parent/teacher communication is preserved; no new role conversation paths were added.
- `20261111140000_cross_portal_consistency.sql`: one additive migration, no tables, destructive operations, backfills, record deletions or policy relaxation. It wraps the existing notice action to generate per-recipient UUID alerts, adds an authorized/idempotent locked chat append, prevents generic conversation replacement, removes family chat from unrelated role projections, and rejects duplicate final record IDs or duplicate class/day registers.
- The same migration extends `school_core_payload` to derive learner averages from valid recorded assessment scores and attendance/absence counts from actual register entries before role filtering. Imported historical summaries remain fallback values only where no recorded evidence exists. Calculations cover recorded evidence for the current class across available dates; they do not invent term boundaries or treat absent marks as zero. Averages are unweighted captured-score means; they are not certified final term marks.
- Daily/weekly/legacy attendance writers now mutate registers only, leaving protected learner profiles alone. No assumed 60-day total is used. Missing absence evidence displays “Not recorded”.
- Term preview uses recorded subject means, distinguishes missing marks/levels/averages, respects both academic-year field spellings and displays a record/current year. Report labels use actual report terms, with a neutral Academic label when no single term is established. Assessment creation requires an explicit term and records its year. The fixed attendance week and invented leadership priorities were removed.
- `npm run test:consistency` runs the existing isolated PostgreSQL suites plus new persistence/cross-role checks. Existing dependencies are reused via `PGLITE_MODULE`; no packages were reinstalled.

## Deployment gate and reproducible checks
This branch still contains the existing Supabase configuration. A Git branch alone does not isolate its backend. Do not push this migration or these functions to the shared project for a test preview. Configure a separate test Supabase project, apply the migration stack there, then deploy `parent-chat` and `parent-workspace` with the matching frontend. Old cached clients that do not send a message request ID must reload; the new endpoint deliberately rejects an unidentifiable send.

Run `node scripts/build.cjs`, then `npm run test:consistency` with `PGLITE_MODULE` pointing to the already installed PGlite module. The SQL fixture is documented in `tests/helpers/platform-db.cjs`; it reuses the pilot migration stack rather than pretending to be a complete Supabase installation. No tests send real invitations, messages, SOS alerts or account mutations.

No production-backed verification was performed in this task. Initial local failures were corrected (new lifecycle startup stub, stale-response test scheduling, fixture DOM selector and SQL UTF-8 BOM); final results are recorded below. The remaining acceptance gaps are substantive and must not be described as a complete platform-wide consistency guarantee.
